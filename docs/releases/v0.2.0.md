# doitdoit v0.2.0

This release is the first intended for the `doitdoit-bin` AUR package. It uses
newly built v0.2.0 artifacts; no v0.1.8 artifact is reused.

## Data-safety changes

- Completed history is now kept forever by default. On the first launch after
  upgrading, `doitdoit` asks once for `forever` or a positive number of days
  and saves the choice before loading or pruning task data. EOF also selects
  forever.
- Retention can be inspected or changed with `doitdoit config retention`,
  `doitdoit config retention forever`, and
  `doitdoit config retention <days>`.
- `doitdoit config move` now refuses every occupied destination, including
  files, directories, and symlinks, and uses create-if-absent publication to
  prevent concurrent overwrites.

Back up both your task JSON file and `~/.doitdoit_config.json` before upgrading,
and verify the backup can be read. Uninstalling the package does not delete
either file.

## Omarchy integration

Theme-change hooks are now opt-in and managed with:

```text
doitdoit config omarchy-hook install
doitdoit config omarchy-hook status
doitdoit config omarchy-hook remove
```

Installation uses Omarchy's hook installer and refuses to replace modified
content. Removal deletes only the exact hook managed by doitdoit. The hook
sends SIGUSR2 to every exact-name `doitdoit` process so all running instances
retint after a theme change.
